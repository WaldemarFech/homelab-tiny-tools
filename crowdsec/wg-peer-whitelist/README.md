# wg-peer-whitelist

Keep your WireGuard peers on a CrowdSec whitelist, automatically.

**Status:** tested (parser backend: unit tests + read-only dry-run against a live
Proxmox setup where a shell predecessor has run every 10 min for months) · `allowlist` backend: experimental

## The problem

You run a WireGuard server and CrowdSec with a bouncer on the same edge, e.g.
`crowdsec-firewall-bouncer` on a Proxmox host or a Traefik bouncer in front of
your services. Your VPN clients connect from home, phone or hotel IPs that
change all the time.

Sooner or later CrowdSec bans one of those IPs:

- the client opened your web apps directly (not via the tunnel) and tripped a
  scenario (a burst of 404s, a failed login, a buggy app retrying),
- or the IP is on a community blocklist because a neighbour behind the same
  CGNAT misbehaved.

With a firewall bouncer, a ban on the client's public IP also drops its
**WireGuard UDP handshakes**. The VPN, the one way you had to get in and fix
things, is cut off too.

The stock `crowdsecurity/whitelists` parser only covers private ranges.
Hard-coding your clients' public IPs doesn't work because they're dynamic.

## How it works

```
wg show all dump ──► parse peers ──► endpoint IPs (public only)
                                      (+ AllowedIPs, + static extras)
                                              │
                ┌─────────────────────────────┴────────────────┐
     backend=parser (default)                     backend=allowlist (experimental)
     render whitelist parser YAML                 diff against `cscli allowlists inspect`
     compare with file on disk                    `cscli allowlists add/remove`
     changed? → atomic write + reload crowdsec
```

1. Runs `wg show all dump` (configurable, e.g. via `pct exec <ct> --` or `ssh`)
   and reads each peer's **current endpoint**, which is the public IP:port the
   peer last sent a valid, authenticated handshake from. The interface line,
   which holds the private key, is discarded right away and never stored or
   printed.
2. Keeps only public addresses. RFC1918, CGNAT `100.64/10`, loopback,
   link-local and ULA are already covered by the stock private-range whitelist.
   `0.0.0.0/0` and `::/0` are never whitelisted.
3. Renders a **standalone** whitelist parser
   (`/etc/crowdsec/parsers/s02-enrich/zz-wg-peer-whitelist.yaml`):

   ```yaml
   # Managed by wg-peer-whitelist - manual edits are overwritten.
   name: local/wg-peer-whitelist
   description: "WireGuard peers - generated by wg-peer-whitelist"
   whitelist:
     reason: "wireguard peer"
     ip:
       - "198.51.100.7"
       - "203.0.113.10"
     cidr: []
   ```

4. Writes the file atomically and runs `systemctl reload crowdsec` **only if the
   content changed**. Peers that left or roamed drop out on the next run, because
   the file is fully regenerated on every run.

A systemd timer runs it every 5 minutes.

### Safety behaviour

| Situation | Behaviour |
|---|---|
| `wg` command fails (container stopped, ssh down) | exit 3, file left untouched (no accidental wipe) |
| zero entries | exit 4, refuses unless `--allow-empty` |
| target file exists but wasn't written by this tool | exit 5, refuses to overwrite |
| nothing changed | no write, no reload |
| concurrent runs | `flock`, second run exits 0 |

## Install

Requirements: Python ≥ 3.8 (stdlib only), `wg` reachable from the host that
runs CrowdSec, root.

```sh
install -m 0755 wg-peer-whitelist.py /usr/local/sbin/wg-peer-whitelist
install -m 0644 systemd/wg-peer-whitelist.service systemd/wg-peer-whitelist.timer /etc/systemd/system/
install -m 0600 systemd/wg-peer-whitelist.default /etc/default/wg-peer-whitelist   # edit as needed

# look before you leap
wg-peer-whitelist --dry-run

systemctl daemon-reload
systemctl enable --now wg-peer-whitelist.timer
systemctl start wg-peer-whitelist.service && journalctl -u wg-peer-whitelist -n 20
```

Check that CrowdSec loaded it:

```sh
cscli parsers list | grep wg-peer-whitelist     # shows as local
```

### Common layouts

| Setup | `WGPW_WG_CMD` |
|---|---|
| WireGuard and CrowdSec on the same host | `wg show all dump` (default) |
| WireGuard in a Proxmox LXC, CrowdSec on the PVE host | `pct exec 100 -- wg show all dump` |
| WireGuard on another machine | `ssh -o BatchMode=yes root@wg-host wg show all dump` |
| Several CrowdSec instances (host + reverse-proxy LXC) | install the timer on each, or run once per target with different `--output`/`--reload-cmd` (e.g. `pct exec 101 -- systemctl reload crowdsec` after writing into the container's rootfs) |

### Options

Every flag has a `WGPW_*` environment equivalent (see `--help` and
`systemd/wg-peer-whitelist.default`).

| Flag | Default | Meaning |
|---|---|---|
| `--wg-cmd` | `wg show all dump` | command that prints the dump |
| `--wg-input FILE\|-` | | read the dump from a file or stdin instead |
| `--source` | `endpoints` | `endpoints`, `allowed-ips` or `both` |
| `--interface` | all | restrict to interface(s) |
| `--include-private` | off | also keep private ranges (needed for `allowed-ips`, which are usually private) |
| `--max-handshake-age SEC` | 0 (off) | drop peers that haven't handshaken recently |
| `--extra IP/CIDR` | | static entries that are always whitelisted |
| `--backend` | `parser` | `parser` or `allowlist` |
| `--output` | `.../s02-enrich/zz-wg-peer-whitelist.yaml` | parser file |
| `--reload-cmd` | `systemctl reload crowdsec` | `''` disables |
| `--allowlist` | `wireguard-peers` | allowlist name (allowlist backend) |
| `--dry-run` / `-n` | | print the diff, change nothing |
| `--print` | | print the generated YAML / value list and exit |

### `allowlist` backend (experimental)

CrowdSec ≥ 1.6.8 has [centralized allowlists](https://docs.crowdsec.net/docs/next/local_api/allowlists/).
Unlike a parser whitelist, an allowlist also stops decisions that come from
**blocklists / CAPI** for those IPs, not just locally detected attacks.
`--backend allowlist` creates the list if needed and adds or removes only the
difference. It only touches the list it is named after.

## Uninstall

```sh
systemctl disable --now wg-peer-whitelist.timer
rm -f /etc/systemd/system/wg-peer-whitelist.{service,timer} /etc/default/wg-peer-whitelist /usr/local/sbin/wg-peer-whitelist
rm -f /etc/crowdsec/parsers/s02-enrich/zz-wg-peer-whitelist.yaml && systemctl reload crowdsec
# allowlist backend:  cscli allowlists delete wireguard-peers
systemctl daemon-reload
```

## Security notes and trade-offs

- **A whitelisted IP is invisible to CrowdSec.** Anything coming from a peer's
  public IP is trusted, including other devices behind the same NAT or CGNAT
  (family Wi-Fi, a hotel, a mobile carrier's shared IP). That's the point of
  the tool, but it also means a compromised device on a peer's network won't
  get banned. Combine it with `--max-handshake-age` so only recently active
  peers stay whitelisted.
- **Endpoints are learned, not configured.** WireGuard only knows a peer's
  endpoint after a valid handshake, which is cryptographically authenticated,
  so attackers can't inject an endpoint without a peer key. Two consequences:
  - Chicken and egg: if a client IP is banned *before* it ever handshakes,
    the firewall bouncer drops the handshake and the IP never gets
    whitelisted. Remove the decision once (`cscli decisions delete --ip …`)
    or add a static `--extra`.
  - WireGuard keeps the *last* endpoint until the peer roams or the interface
    restarts, so an old IP can stay whitelisted for a while.
    `--max-handshake-age` limits that.
- **Parser whitelist ≠ blocklist protection.** The parser backend stops local
  detections only. If an IP arrives via a community blocklist, use the
  allowlist backend.
- The tool runs as root because `wg show` and the CrowdSec config need it. It
  never prints keys, uses no network access of its own, and writes one file.
- Full-tunnel peers (`AllowedIPs = 0.0.0.0/0`) are never turned into a
  "whitelist everything" entry.

## Why a separate file and not `whitelists.yaml`?

Editing the hub-managed `crowdsecurity/whitelists` parser in place marks it as
*tainted*, so hub upgrades skip it or ask about it, and any sed-based
"managed block" inside it is fragile. A separate `local/…` parser
survives `cscli hub upgrade` and is trivial to remove.
